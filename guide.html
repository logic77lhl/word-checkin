WHY这篇教程解决什么

不配也能用——页面会自动进纯本地模式。这篇只解决一件事：让进度能跟着账号走。

配完之后你会得到：

  • 换电脑、换手机，登录同一个账号就能接着背
  • 游客期间的进度能带到账号里（会弹窗让你选合并方式）
  • 两台设备同时学同一批词也不会互相覆盖
先说清楚成本 Supabase 免费额度对个人使用足够：数据库 500 MB（你一年的进度大约几百 KB）、每月 5 GB 流量。 唯一要注意的是项目连续 7 天没有任何请求会被自动暂停，重新点一下 Restore 就好。
① 建项目 ② 建表 ③ 填配置 ④ 部署 ⑤ 登录方式 合并规则 自检 常见错误 安全

STEP 01建 Supabase 项目

5 分钟。注册免费，不需要信用卡。

1
注册并新建项目 打开 supabase.com/dashboard，用 GitHub 登录 → New project。
字段填什么
Nameword-checkin（随便取，用户看不到）
Database Password点 Generate，复制存到密码管理器（后面基本用不到，但丢了要重置）
RegionSoutheast Asia (Singapore)，国内访问延迟最低
PlanFree
2
等它变绿 状态从 Setting up project… 变成 Active 大约 1–2 分钟。这期间别急着下一步。
3
记下两个值 Project Settings → API（新版叫 API Keys）里：
  • Project URL：https://xxxx.supabase.co，也可以直接看浏览器地址栏里 /project/ 后面那段
  • anon public 或新版 publishable key：eyJ… 或 sb_publishable_…
只看这两个，别的都不要复制 同页面的 service_role / sb_secret_… 会绕过所有权限。它一旦出现在前端，等于把整个数据库交出去。

STEP 02建表 + RLS

3 分钟。一次粘贴，跑完就不用再管数据库。

Supabase → SQL Editor → New query，把下面整段粘进去执行：

create table public.progress (
  user_id     uuid primary key references auth.users(id) on delete cascade,
  data        jsonb not null default '{}'::jsonb,
  revision    bigint not null default 1,
  updated_at  timestamptz not null default now(),
  constraint progress_size check (pg_column_size(data) <= 2097152)
);

alter table public.progress enable row level security;

create policy "own progress select" on public.progress
  for select using (auth.uid() = user_id);
create policy "own progress insert" on public.progress
  for insert with check (auth.uid() = user_id);
create policy "own progress update" on public.progress
  for update using (auth.uid() = user_id) with check (auth.uid() = user_id);
create policy "own progress delete" on public.progress
  for delete using (auth.uid() = user_id);

-- 给登录用户表权限；RLS 负责把它们限定成「只有自己那一行」
grant select, insert, update, delete on public.progress to authenticated;
最后那行 grant 别漏 少了它，前端会稳定收到 403 permission denied for table progress。 表建出来了、RLS 也开了，但角色根本没拿到读写权限——这是最容易卡住的地方。

怎么算过：左侧 Table Editor 能看到 progress 表，并且表名旁边标着 RLS enabled。

为什么只有一张表 整个进度是一个 JSON（设置、每词复习状态、每日记录、徽章……），塞进一行的 data 字段。 读写都是一次请求，不用 join。等真要做排行榜时再拆表。

STEP 03把 URL 和 key 喂给页面

2 分钟。走环境变量，key 不进仓库。

静态页面在浏览器里没有 process.env，所以做法是构建时注入：脚本从环境变量生成 config.js，这个文件已经被 .gitignore 忽略。

本地

在仓库根目录建 .env.local：

WQ_SUPABASE_URL=https://xxxx.supabase.co
WQ_SUPABASE_ANON_KEY=sb_publishable_xxxx

然后生成配置：

node scripts/gen-config.mjs

线上（GitHub Actions）

把同样两个值存成仓库 Secret，部署时由 workflow 读出来生成 config.js：

gh secret set WQ_SUPABASE_URL --body "https://xxxx.supabase.co"
gh secret set WQ_SUPABASE_ANON_KEY --body "sb_publishable_xxxx"
publishable key 本来就是公开的 它会被打包进页面、出现在浏览器网络面板里，这是设计如此。真正的安全边界是数据库里的 RLS 策略，不是这个 key 的保密性。走环境变量只是为了让配置和代码分离，换环境不用改代码。

STEP 04部署到 GitHub Pages

1 分钟。因为要生成 config.js，必须用 Actions 发布。

1
改发布源 仓库 Settings → Pages → Build and deployment → Source，从 Deploy from a branch 改成 GitHub Actions。
2
推一次代码 .github/workflows/pages.yml 会自动跑：生成 config.js → 打包 → 发布。
3
确认 打开 https://<用户名>.github.io/<仓库名>/config.js，能看到 window.WQ_CONFIG 就算成功。
还是从分支发布会怎样 Pages 会直接把仓库原样发布，里面没有 config.js，页面就会一直停在「纯本地模式」，登录页提示「还没有配置 Supabase」。功能不受影响，但登录用不了。

AUTH开通登录方式

邮箱登录开箱即用；GitHub 登录更顺，但要额外建一个 OAuth App。

A. 先填回调地址（必做）

Supabase → Authentication → URL Configuration：

字段填什么
Site URLhttps://<用户名>.github.io/<仓库名>/
Redirect URLs再加两条：
https://<用户名>.github.io/<仓库名>/login.html
http://localhost:4173/login.html
漏了这条的典型表现 点登录 → 跳出去 → 回来还是未登录，或者直接被打回首页。Supabase 只会往白名单里的地址回跳。

B. 邮箱魔法链接（默认，不用配）

用户填邮箱 → 收到一封邮件 → 点链接直接进来，不设密码。

两个限制 ① 免费版自带发信服务每小时只能发几封，只适合自己测；要给真实用户用，在 Authentication → Emails → SMTP 换成自己的发信服务。
② 链接必须在同一台设备、同一个浏览器里打开（PKCE 机制），换设备会失败并给出提示。

C. GitHub 登录（可选，3 分钟）

去 GitHub → Settings → Developer settings → OAuth Apps → New OAuth App：

字段填什么
Application name随便，比如 词途 WordQuest
Homepage URL你的站点地址
Authorization callback URLhttps://<项目ref>.supabase.co/auth/v1/callback

拿到 Client ID 和 Client Secret，填进 Supabase → Authentication → Sign In / Providers → GitHub，打开开关保存。

填完不用改代码 登录页启动时会请求 /auth/v1/settings 探测可用的登录方式：GitHub 没开就自动隐藏按钮，开了就自动出现。

MERGE多设备怎么合并

不会整块覆盖——每次写入都带版本号，撞车就拉下来合并再重试。

写入时带 revision 做乐观锁：版本号对不上说明别的设备刚写过，于是拉最新 → 按下面的规则合并 → 再重试，最多 3 次。

数据规则为什么
单词记录按 last 取较新那条；听说计数取较大值复习等级宁可保留更新的判断，计数不重复累加
每日记录按日期取并集，同一天的计数取较大值两台设备同一天学，求和会重复算
徽章取并集，解锁日期取较早拿到过就是拿到过
技能计数逐项取 max同一次练习只该算一次
自定义词表按单词去重（大小写不敏感）两边都导入过同一个词很常见
设置按 updatedAt 取较新换了词库/目标要跟人走
XP取较大值宁可少算，不重复加分

第一次在设备上登录时，如果这台设备还有游客进度，会弹窗让你选：合并 / 只用云端 / 只用本机。选完就写进当前账号的本地命名空间，下次不再问。

本地怎么隔离 游客用 wordquest-v1，登录后用 wordquest-v1:<user_id>。 共用电脑换账号不会串数据，退出登录回到游客那份。

CHECK跑一遍自检

不用登录，直接查配置和表权限。

自检只能验证「配置有没有接上、表在不在、权限对不对」，登录本身还是得你在登录页试一次。

ERR常见错误对照

按页面上的报错原文找。

看到什么原因怎么办

SEC安全清单

前三条是硬要求，后面是习惯。

  • service_role / secret key 永远不进前端。它绕过 RLS，放进去等于公开数据库。
  • 每张用户表都开 RLS，并且用两个账号实际测一次越权：A 读 B 的行应该拿到空数组。
  • 表级 grant 要单独给。RLS 是「行级」过滤，它管不了「这个角色连表都碰不到」。
  • 限制 data 大小（本项目用 check (pg_column_size(data) <= 2097152) 卡在 2 MB）。
  • 提供「导出」和「删除云端数据」，用户能自己把数据带走或删掉。
  • 公开仓库没问题——前端代码本来就是公开的；要注意的是别把 .env、备份 JSON、用户数据提交上去。
最后一步 配完去应用里登录一次，学几个词，再开无痕窗口登录同一个账号——进度能回来，说明整条链路通了。
